# i18n — cycle de vie d'une langue (V2-21a)

Ce document décrit comment le produit gère ses langues : le **registre**, le
cycle de vie d'une langue, et le rituel d'ajout d'une langue future.

> **Principe directeur** — Le produit n'offre JAMAIS que les langues
> **publiées**. Aucune liste de langues codée en dur, nulle part (invariant 8
> étendu aux langues, cf. `CLAUDE.md` invariant 15). Une langue en brouillon ou
> en relecture est invisible pour tout utilisateur.

## Le registre : la table `languages`

Table introduite par la **migration 019** (seed dans `db/seed.sql`) :

| colonne | rôle |
|---|---|
| `code` | code ISO court (`fr`, `en`, `es`, `nl`, `de`, `it`, `sq`) — clé primaire |
| `name_native` | nom natif affiché dans le sélecteur (`Français`, `Nederlands`, `Shqip`…) |
| `status` | `draft` \| `in_review` \| `published` — **le seul** qui décide de la visibilité |
| `sort_order` | ordre d'affichage (10, 20, 30…) |
| `register_note` | consigne de **registre** (vouvoiement/tutoiement…) imposée au modèle à la génération |

Le registre est **la source unique** des langues offertes. Le lisent :

- **Backend** : `repo.published_languages(conn)` / `repo.published_language_codes(conn)`.
- **Enrich / CLI** : `db.published_language_codes(conn)` (repli des cibles de traduction).
- **SSR du guide** : lecture directe de la base (`api/routers/guide.py` charge la
  carte code→nom natif et la passe à `guide_page.render_guide`).
- **Front** : `GET /languages` (endpoint public) via `frontend/js/languages.js`
  (`publishedLanguages()` / `publishedLanguageCodes()`), consommé par le menu de
  partage et la modale « langue du locataire ».

Le `properties.published_langs` d'un logement (langues traduites pour CE guide)
est **croisé** avec le registre à la lecture : une langue dépubliée globalement
disparaît du guide même si elle reste dans `published_langs`.

## Cycle de vie d'une langue

```
draft  ──(génération + relecture)──▶  in_review  ──(corrections importées)──▶  published
  ▲                                                                                │
  └───────────────────── (dépublication à chaud, non destructive) ────────────────┘
```

- **`draft`** — la langue existe au registre, ses libellés peuvent être générés,
  mais **rien n'est offert** à l'utilisateur.
- **`in_review`** — export envoyé à un relecteur (toujours invisible).
- **`published`** — la langue apparaît partout (sélecteurs, partage, détection).

Le passage d'un état à l'autre est un simple `UPDATE languages SET status=…` :
c'est une **opération**, pas un développement, et elle prend effet **sans
redéploiement**. Le **seed ne touche jamais `status`** (un rejeu ne dépublie ni
ne republie une langue).

État actuel (V2-21a) : `fr`/`en`/`es` = `published` ; `nl`/`de`/`it`/`sq` =
`draft` (générés puis relus, publiés une à une en missions V2-21b…n).

## Registre de langue (`register_note`)

La décision de registre est tranchée **une fois par langue** et imposée au
modèle à chaque génération (la cohérence prime sur la qualité ponctuelle). Défauts
alignés sur le ton du guide FR (vouvoiement) :

| langue | registre |
|---|---|
| de | vouvoiement (Sie) |
| nl | vouvoiement (u) |
| it | voi (le guide s'adresse au groupe de voyageurs) |
| sq | forme de politesse (ju) |

Ajustable en base (`UPDATE languages SET register_note=… WHERE code=…`), jamais
en dur dans le code.

## Ajouter une langue future (PT, CA…)

1. Insérer la ligne au registre en `draft` (`INSERT INTO languages …`) avec son
   `name_native`, un `sort_order` et sa `register_note`.
2. Générer l'inventaire des libellés (outillage volet 2/3 de V2-21a).
3. Faire relire (export CSV → correction → réimport).
4. Publier : `UPDATE languages SET status='published' WHERE code='pt';` — la
   langue apparaît immédiatement partout.

Rien à redéployer, aucune liste de langues à modifier dans le code.

## Vérification (garde-fou i18n)

Aucune liste de langues ne doit **décider de ce qui est offert** hors du
registre. Les seuls résidus admis sont des **libellés d'affichage** (avec repli
sur le code brut) :

```bash
grep -rnE "'(en|es|de|nl|it|sq)'" backend/api frontend/js
```

Le test clé (`tests/test_api.py::test_unpublishing_a_language_removes_it_everywhere`)
vérifie qu'une langue passée en `draft` disparaît de l'endpoint, du sélecteur du
guide et de `/g/{token}/data`.
